---
name: read-readmes
description: Read project README files for context when working in a repository, and change them only when the user explicitly requests README changes.
---

Read the project's root README before starting work. Read README files in relevant subdirectories before working in those areas. Treat README filenames case-insensitively and include formats such as README, README.md, and README.rst.

Use these files to understand the project's purpose, setup, conventions, and relevant workflows.

Do not create, edit, rename, or delete README files unless the user explicitly asks for README changes. A request to implement a feature, fix a bug, refactor code, or update documentation generally does not by itself authorize README changes. An explicit request already made in the conversation is sufficient; do not ask for confirmation again.

If your work makes a README inaccurate, leave it unchanged and briefly mention the discrepancy in your final response. Continue the authorized work without stopping to seek permission for a README update.

When README changes are explicitly requested, keep them within the requested scope.
